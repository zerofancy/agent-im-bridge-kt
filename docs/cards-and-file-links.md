# 卡片与本地文件链接

[返回项目首页](../README.md)

流式卡片、停止状态、答案快照及编辑器文件定位。

## 卡片中的本地文件链接

新生成的 `.html` / `.htm` 文件链接（大小写不敏感）直接在浏览器预览，不启动编辑器、不自动倒计时关闭；不兼容旧版 `/open` 链接的 HTML 跳转。预览使用隔离源沙箱，支持内联样式和脚本、data 图片及 HTTPS 图片；不提供同目录资源读取，外部脚本、网络请求和表单受限，避免本地文档调用编辑器控制接口。依赖相对 CSS、JS 或图片的页面暂需改为自包含 HTML。

飞书和 Telegram 实例启动时会绑定 `127.0.0.1` 的系统分配端口，端口仅在本次运行内固定，不持久化。回复中的 Markdown 文件链接（如 `[源码](src/Main.kt:47:2)`、绝对路径、`file:` URL 和 `#L47` 行号）会转换为本地打开页面链接。工作目录在创建卡片时固定，支持 `/cd` 后的会话目录；代码块、行内代码、图片及普通网络链接不转换。

Telegram 的流式回复、最终富文本回复和普通文本回退均转换文件链接；富文本任务创建时固定工作目录。普通文本回退保留 Markdown 链接文字与 HTTP 地址，具体点击行为取决于客户端。

点击后页面自动请求本地服务，通过编辑器 CLI 打开项目目录并定位文件行列，无需选择应用。macOS 检测到标准位置的 Trae CN CLI 时使用 Trae CN，否则使用 VS Code；CLI 必须已安装，VS Code 支持标准 macOS 安装路径或 PATH 中的 `code`。服务运行的电脑必须与点击链接的电脑相同。服务重启后旧卡片链接可能失效，请让 Agent 重新发送。

链接校验签名与 Host，编辑器启动另校验同源 POST。点击时重新解析符号链接并检查真实目标是普通文件，允许工作目录外的本机文件；HTML 预览要求链接路径和真实目标均为 HTML 类型。不执行任意 shell 命令，查询参数不写日志，编辑器打开页不加载第三方资源。原始答案快照仍保存模型的原链接，不保存本次运行的本地签名链接。超长卡片仍按原规则回退文本。

## 流式卡片回复

### 可选 COT 过程展示

实例 JSON 配置新增 `"feishuProgressMode": "cot"`，重启生效；缺省为 `cot`，显式设为 `cardkit` 可回退，非法值启动失败。不自动修改 DEV 或 PROD 已有配置。COT 仅替换飞书 IM 的过程展示，最终结果卡片、图片交付、评论旁路与未知发送保护保持原有流程。工具显示实际安全名称（MCP 包括服务名），原生命令执行和 OpenCode bash/shell 显示脱敏命令摘要，超长明确截断；不展示其他参数或原始输出。详见 [接入 Spec](feishu-cot-integration-spec.html)。

Codex / Traex 使用原生 thread/turn 事件，OpenCode 使用当前助手消息快照；只上报公开说明和安全工具状态，不发送隐藏推理、工具参数或原始输出。公开说明在完整 item 确认后脱敏上报，不逐 token 转发。缓存为 32 个有界事件，溢出停止中间过程上报，保留独立终态槽。单轮最多同时展示 4 个未结束文本和 4 个未结束工具，为收尾预留容量；未确认工具结果明确标为过程记录不完整，不宣称成功。

Create 明确拒绝才降级为原过程卡片；创建结果未知不重建，Update 结果未知不重放。每次请求持久化创建意图、已知 COT ID、事件计数和关闭尝试；重启仅尽力关闭已知且未尝试 Complete 的旧过程，不重跑 Agent、不重发答案。已尝试关闭但结果未知的记录只保留诊断。状态记录不包含消息正文，沿用环境隔离目录和私有文件权限。

离线回归不能证明应用 COT 权限或客户端折叠、通知效果；启用前仍须在 DEV 按 Spec 验收。COT 收尾不阻塞最终结果发送，但请求清理会有最多 5 秒的过程收尾预算。

飞书原生图片结果会复用媒体交付流程：权威正文先通过统一文字入口发送，再逐张发送原生图片消息，最后用结果卡片给出交付摘要。纯图片不发送空正文；图片不嵌入卡片，此时一轮可以超过两条消息。只有全部选中图片确认送达且无校验问题才标记整体完成，发送状态未知时不自动重发。文档评论仍不支持图片，桌面沿用本地图片展示。详细规则见 [原生图片回复 Spec](native-image-reply-spec.md)。

文档评论在聊天服务入口直接旁路卡片回复，不创建 IM 过程卡片或结果卡片，不进入卡片进度与收尾流程；正文仍通过原评论回复路由交付。

飞书 IM 模型任务默认使用 Card JSON 2.0 双卡片：过程卡片实时显示公开进度与工具名称/状态，不展示答案增量；轮次结束后向原始请求发送一张新的静态结果卡片，展示权威最终答案，不重复执行过程。过程卡片折叠保留，注明结果独立发送，不撤回旧卡片、不另加完成通知。新消息可能产生普通通知，但不保证免打扰或停留聊天时的提醒表现。其他渠道及文档评论保持原有交付方式。

即时命令继续文本回复，停止仍使用 `/stop`，只有后端确认轮次结束才显示已停止。没有模型自动超时。 `/stop` 的文本确认由独立的后端结束信号触发，不等待卡片或 Typing 清理；清理期间 `/status` 显示“后端已结束，回复清理中”。后端自行中断且卡片无法收束时补发文本说明。停止不新增结果卡片；原过程卡片标记为“已终止”，已生成的部分答案和执行过程保留在默认折叠、可展开的面板中，引用时明确标记为未完成。结果消息已提交后与停止竞争时可能已经送达，不尝试撤回。

机器人应用需开通 `cardkit:card:write`，并保留原有消息发送权限；已有应用需在飞书开放平台为对应环境的机器人增加权限并发布版本。客户端要求飞书 7.20+。过程卡片创建或更新失败不阻断结果卡片。结果卡片资源创建失败或消息明确拒绝时回退最终文本，不重跑模型；发送超时、断连或响应不明时不自动文本兜底或盲目重发。结果卡片超出 JSON 字节预算时，新结果卡片提示查看后续文本，再分段发送完整答案；只有全部分片确认才将过程标记为完成。分片期间取消／失败不重发整份答案。

Codex / Traex 使用 app-server 的 `item/started`、`item/completed` 和 `item/agentMessage/delta`。过程卡片仅展示明确标为 `commentary` 的公开说明与命令进度；答案增量只保留供停止时展示部分输出，正常结果使用轮次结束的最终答案。执行命令会显示实际命令（含参数、多行内容）及已返回的退出码；完成事件未重复提供命令时沿用开始事件的命令。命令最长显示 1000 个 UTF-16 代码单元，超出时明确标记截断。不展示原始 reasoning 或工具输出，命令仅用于卡片展示、不写入日志。进度保留最近 12 项的有界摘要，不作为完整执行日志。

每轮有独立且随聊天任务结束的更新协程，约每秒合并进度；同应用卡片请求共用限流，单卡操作顺序递增。流式模式临近 10 分钟时按需续开，完成和异常清理时关闭。外部网络完全不可用或进程强制退出时，最后一次卡片收束可能失败。 SDK 调用异常在独立边界转换为可恢复失败，请求构造及内部错误仍保留原有致命错误处理。失败日志仅记录操作、分类、业务码、可用的 HTTP 状态、异常类型和尝试次数，不携带原始异常正文或响应。

结果卡片通过自建 HTTP 封装发送，复用 SDK token manager，不新增权限。交付记录保存在应用答案目录的 `deliveries/` 下，发送前原子保存原请求、稳定 UUID、正文和阶段，确认后保存结果消息 ID、时间；文本降级记录待发送分片及已确认数量。记录包含正文，按答案快照同等保护，不作为日志上传。重启不自动重放未确认发送；无法按现有信息只读确认时保留未知状态。相同已确认请求不会再次发送结果。过程收束／关闭清理不负责发送新结果，避免重复通知。

机器人卡片的答案快照保存在 `environments/<环境>/card-answers/<应用哈希>/`，目录/文件权限为 700/600，随环境独立持久化。引用卡片或对其点表情时，先通过飞书读取并校验原消息，再读取该消息的答案；重启后仍可引用。执行中的卡片引用会明确提示尚未得到最终答案，过程不会被误当作最终回复。此目录保存消息正文，不应作为日志上传；目前不自动过期，删除后旧卡片的本地引用能力将丢失。

长答案的短结果卡片在文本分片全部确认前，引用快照只保存“完整回复尚未确认送达”的占位说明，不能读取尚未完整交付的权威正文。分片失败、取消或重启后仍保留占位；全部确认后才写入完整引用快照。权威正文独立保留在交付记录中，不因引用快照更新而重发消息。

设计背景及能力边界见 [流式卡片调研](feishu-streaming-cards-research.html)。离线测试覆盖 SDK 请求、重试、卡片状态、引用/表情和聊天调度；真实客户端效果需在 dev 验证。
