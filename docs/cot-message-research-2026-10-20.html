2. 三个接口

生产飞书 Base URL 为 https://open.feishu.cn；使用机器人所属应用的 tenant_access_token，Content-Type 为 application/json;charset=utf-8。目标应用的实际权限和调用结果仍需在 DEV 验证，不假定已有授权必然覆盖。

阶段接口关键数据
创建POST /open-apis/im/v1/message_cot?receive_id_type=chat_idreceive_id、origin_message_id、reply_in_thread；保存返回的 cot_id 和 message_id。
追加过程PUT /open-apis/im/v1/message_cotmessage_id、cot_id、events；事件含 event_type、timestamp、content。
完成收口POST /open-apis/im/v1/message_cot/complete/{cot_id}?message_id={message_id}&reason=done请求体为空。正常完成用 done；失败或用户中断用 error；timeout 仅供内部兜底调用，外部调用不可使用。

events[].content 必须是序列化后的 JSON 字符串，不是直接嵌套的对象。运行、文本、工具都使用稳定 ID 关联；同一 COT 的事件串行发送。

3. 如何生成目标体验

  1. 请求真正开始执行时 CreateCOT，再发送 RUN_STARTED；不要为排队中的每条消息立即启动运行，也不要为 /stop 创建新 COT。
  2. 阶段文案映射为 TEXT_MESSAGE_START / CONTENT / END；工具映射为 TOOL_CALL_START / END / RESULT。END 表示参数阶段结束、工具开始运行，不代表工具执行成功。
  3. 官方事件指南也支持 REASONING 系列，但只可输出公开进度摘要，不能发送模型原始隐藏推理。
  4. 正常运行发送 RUN_FINISHED，然后 CompleteCOT(done)；失败发送 RUN_ERROR，然后 CompleteCOT(error)。
  5. 按 Playground 的用户中断示例，原生中断确认后发送 RUN_FINISHED(status=interrupted)，再 CompleteCOT(error)；不能把中断请求已接受当成任务已停止。
  6. 最终答案继续通过现有独立结果卡交付；原生折叠、状态和工具分组由飞书渲染。

不要把 AG-UI 的所有事件都当作已实现：Playground 指南将 STEP_STARTED、STEP_FINISHED、STATE_SNAPSHOT 等标记为不支持。首期仅采用已支持的运行、文本、工具事件。

4. 通知、隐藏与版本边界

CreateCOT 字段官方说明本项目建议
enable_badge是否推送红点过程设置 false，独立结果消息承担通知；实际未读行为需客户端验收。
update_feed_rank是否顶会话列表过程设置 false，避免过程持续打扰会话排序。
cot_hidden是否在完成后隐藏 COT若要保留可展开过程，设置 false；隐藏模式另行选择，不默认丢失过程入口。

上述三个参数在接入参考的 7.75 更新中记录。7.73 起停止按钮默认仅私聊可见，群聊默认不可见，群聊增强按灰度处理。不能依赖它替代本项目已有鉴权和 /stop 控制。

5. 接入项目需要改什么

  • 增加独立 FeishuCotClient 和有生命周期的 COT reporter，复用现有 HTTP、token manager 和路由；不让模型自行调用飞书。
  • 保留 CardKit 进度模式作为可选兼容路径，COT 作为新的展示策略。COT 初始化失败可降级，但不能重复启动 Agent。
  • 当前 AgentProgress 只有 process、answer 两个渲染字符串。若需工具分组，必须在 reducer 丢弃结构之前保留工具 ID、名称与状态；不要反解析 Markdown 文本伪造事件。
  • 现有进度快照允许合并，COT 却需要有序生命周期事件。可合并文字增量，不能丢失 RUN_STARTED、工具边界及最终收口；采用有界队列、单 COT 串行上报。
  • COT 是展示旁路：网络失败不能破坏 FIFO、占槽、中断与最终答案。初始化结果不明时不可盲目创建第二条过程消息；先明确恢复或降级策略。
  • 保留原有会话隔离与用户校验，最终卡、原生图片及文档评论仍走既有交付链路；文档评论不是此次 COT 接入目标。

6. 约束与验收

接入参考列出：单条 event 长度不超过 4096，单次最多 50 条；单 bot 更新 50 QPS、单 COT 更新 20 QPS。按保守字节预算分片并节流，不能依赖短期实测超限成功。总量限制的评论存在表述歧义，不据此承诺可无限追加。

DEV 验收至少覆盖：最小创建—更新—完成；中途查看后最终消息通知；工具失败但运行继续；正常完成；/stop 确认后收口；并发聊天隔离；话题路由；请求失败、重复和乱序；进程退出；内容脱敏；原生图片交付与结果未确认。
