01 · 已确认的能力

问题观察结果对接入的意义
新建会话实测 退出 0；依次出现 thread.started、turn.started、item.completed、turn.completed。可以复用现有生命周期事件模型。
显式 resume实测 新进程返回同一 UUID，正确回答上一轮设定的探测标记。保存 thread_id，之后显式续接；禁止依靠 --last。
最终输出实测 -o 文件含最终答复；stdout 可包含多条 agent_message，且未携带 phase。继续使用独立答案文件，不能拼接所有 agent_message 当成最终答复。
不存在的 UUID实测 退出 1、stdout 为空、stderr 返回明确的 no rollout found 诊断。该版本与现有 Codex 的精确匹配规则相同；仍保留后端级识别入口。
续聊时更换目录实测 -C 新目录生效，但 UUID 和旧标记仍保留。CLI 不会因目录改变自动清空上下文；/cd 的新会话行为必须由 Bridge 实现。
只读权限实测 新建及续聊的 turn_context 均为 approval_policy=never、sandbox_policy=read-only。工具写入探测文件被 Operation not permitted 拒绝。显式传入本地 sandboxMode；不依赖 CLI 默认权限。
工具失败与轮次失败实测 写入工具退出 1，但模型解释了拒绝结果，CLI 退出 0 且 turn.completed。工具失败不等于 AgentResult.Failure；按轮次状态、进程退出码和最终文件判断。

共完成 5 次成功模型轮次（一个新会话及其 3 次续聊，另一个隔离目录的新会话），另做 1 次缺失会话探测。未调用已有用户会话；只读取本次探测对应的历史记录。

02 · 已验证的调用方式

下列形态已在本机验证。生产实现使用 ProcessBuilder 参数数组，正文写入 stdin，不经 shell 拼接。占位路径和 ID 应替换为本次任务值。

新建

traex -a never exec \
  --sandbox read-only \
  --skip-git-repo-check --color never \
  -C /absolute/workspace \
  --json --output-last-message /absolute/task/answer.txt -

续聊

traex -a never exec \
  --sandbox read-only \
  --skip-git-repo-check --color never \
  -C /absolute/workspace \
  resume --json --output-last-message /absolute/task/answer.txt \
  SESSION_UUID -

-C、--sandbox、--color 放在 exec 的 resume 子命令之前；根级 -a never 和 -c 'approval_policy="never"' 两种方式均已验证。不要添加 --ephemeral，否则无法满足持久续聊。

stdout 样例（会话 ID 已替换）

{"type":"thread.started","thread_id":"00000000-0000-4000-8000-000000000001"}
{"type":"turn.started"}
{"type":"item.completed","item":{"id":"item_0","type":"agent_message","text":"OK"}}
{"type":"turn.completed","usage":{"input_tokens":15550,"cache_creation_input_tokens":0,"cached_input_tokens":0,"output_tokens":5,"reasoning_output_tokens":0}}

收到 thread.started 后执行挂起的会话提交回调，等待落盘完成再读后续事件。resume 返回的 ID 必须与请求 ID 一致；重复出现不同 ID 或缺少终态均按协议异常处理。usage 是可选统计信息，不应成为成功判断的必要条件。

缺失会话诊断

Error: thread/resume: thread/resume failed: no rollout found for thread id SESSION_UUID (code -32600)

该探测没有输出 thread.started 或 turn.started。只有同时满足“非零退出、匹配指定 ID 的可信诊断、本轮未开始、未发现新会话”，才映射 SESSION_MISSING 并允许最多一次新建。不能从模型正文搜索错误关键词。

stdout JSONL 并非完整工具审计流。只读探测确实执行了 shell 工具，但 stdout 只包含两条 agent_message；具体工具调用与退出 1 的结果存在 rollout 的 history_mutation.items 中。不要把本地 rollout 格式当成 exec 输出格式解析。

这与 TraeX Guide 对非交互输出的说明一致：exec 事件不是完整本地会话镜像，只需结果时优先使用 -o。

03 · 状态目录与认证

项目当前版本的观察证据
执行入口~/.local/bin/traex → ~/.local/share/traex/current/traex本机符号链接与 --version
共享配置根默认 ~/.trae；主配置 traecli.tomlexec --help、用户手册、本机目录
运行时根默认 ~/.trae/cli；含 auth.json、sessions、日志及 SQLite 状态目录检查及探测会话落盘
仅 TRAE_HOME指定共享根后，运行时使用其 cli 子目录独立目录 login status 探测创建 cli/tmp 等目录
仅 TRAECLI_HOME直接指定运行时目录，不再追加 cli独立目录探测创建 runtime/tmp；模型会话写入 runtime/sessions
两者同时设置运行时采用 TRAECLI_HOME，TRAE_HOME 保留共享根身份相同探测与隔离模型轮次
CODEX_HOME单独改为一个空目录，没有将 Traex 运行时导入其中；原登录状态仍可见新目录未产生文件，login status 退出 0

建议解析规则：sharedRoot = TRAE_HOME ?: ~/.trae，runtimeRoot = TRAECLI_HOME ?: sharedRoot/cli，均规范化路径。空值、相对路径和符号链接的环境变量边缘行为尚未逐项测试，Bridge 应明确自己的校验规则。

Traex 帮助的 --ignore-user-config 文案仍出现 CODEX_HOME/config.toml，不能据此把 Codex 目录用于 Traex。本次未使用该开关；应保留用户配置和项目规则。

login status 不能作为唯一启动门槛

空运行时目录的 login status 返回 1；随后相同隔离环境执行 exec 却成功，并生成 auth.json 和会话文件。说明当前本机环境存在执行时认证路径。用户手册介绍了 Git/本机身份与 SSO 登录方式，但本次没有检查凭据内容，也没有确认具体触发了哪种认证机制。

启动时只检查可执行文件及支持的参数能力；认证诊断应脱敏。不要因为 login status 返回非零就推断模型请求一定不可用，也不要由 Bridge 复制凭证。

已重新核对本轮更新的代码：AgentRunner.run 和 onSession 现为挂起接口，CodexRunner 已采用结构化协程。因此直接沿用当前接口与进程清理机制，不恢复旧的同步接口或线程池。

  1. 后端选择：第一版增加 --backend codex|traex 和 --traex-bin，默认仍为 Codex；仅初始化选中后端。使用明确的 traex 命令，避免 traecli 别名指向旧版 CoCo。
  2. 公共执行器与协议适配：抽出可复用的协程进程管理；Traex 适配器负责参数、状态目录、版本信息及错误识别。已验证的事件解析可以共享，版本差异保留独立测试入口。
  3. 会话隔离：SessionKey 加 backendId，将 codexHome 泛化为 runtimeRoot；键为应用、聊天、后端、规范化工作目录及运行时根。ChatKey 同样区分后端与运行时根。v1/v2 数据迁移为 Codex 绑定，不传给 Traex。
  4. 持久化：目录选择与 session 绑定继续原子提交；迁移失败不覆盖源文件。onSession 提交必须被等待，取消时也等待其清理结束。
  5. 用户提示：将“Codex 执行失败”等固定文案改为后端显示名；日志附 backendId，仍不输出正文、stderr 原文和凭据。

按最新项目约定保留的行为

  • /status、/pwd、/help、/stop、/cd 是即时控制命令，不排入模型 FIFO、不占用模型槽位；未知斜杠命令原样交给 Agent。
  • /cd 必须带路径，聊天忙碌时拒绝。切换不同目录清除目标旧绑定，切回也新建；落盘成功但回复失败不回滚。
  • /stop 取消当前聊天任务及命令接收时已有队列；新请求等清理完成再执行，按请求身份释放槽位。
  • 模型任务不设自动超时或无进展超时；仅保留发送、连接及进程清理的技术超时。本次探测脚本的限时只用于调研保护，不是产品设计。
  • 保持同聊天 FIFO、跨聊天并发上限、用户校验、群聊明确 @、SDK 去重和原消息回复。
  • 访问模式仅由本地 sandboxMode 决定，重启生效；固定不请求交互审批，不通过重试放宽权限。
