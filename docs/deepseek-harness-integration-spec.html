01 · 结论与范围

建议：新增 deepseek 后端，Kotlin 直接连接独立 dsh --profile acp 子进程的 ACP JSON-RPC。复用 Bridge 的调度、会话、鉴权及消息展示；配套一个小型 Cordis 策略插件，保证本机权限配置在创建及恢复后始终生效。

ACP 已具备持久化空会话、多会话并发、原生取消和单会话关闭，能够适配现有控制命令。它输出已提交消息的语义块，不提供 Web UI 的实时 token 增量；界面应展示阶段、工具状态和逐条完成的正文。

  • V1 包含：文本往返、跨轮续聊、重启恢复、/new、/resume、/cd、/stop、新群初始化、FIFO、跨聊天/话题并发、工具进度、DEV/PROD 独立配置及部署。
  • 默认仍为 read-only；目标支持三种现有 sandboxMode。受限模式须通过对应平台的实际拒绝写入测试后才可声明支持，缺少沙箱或策略插件时拒绝启动，不能放宽成 full access。
  • V1 复用现有附件路径/链接与文件定位；原生图片输入输出、语音、Harness Web 展示卡、计划审批、原生问答 UI、MCP 配置管理及外部桌面会话导入另行适配。
  • 保持 Codex、Traex、OpenCode、Doubao 行为；不替换模型服务 API、不实现新的调度器、不连接或停止用户正在运行的 Harness 桌面服务。

本文保留设计契约与调研证据；适配代码及后续验证记录见第 12 节，实际验证范围以该节为准。

03 · 为什么采用 ACP

路径能力与限制决定
ACP stdiosession/new、resume、prompt、cancel、close、list；同连接多会话；语义消息和工具事件。V1 主路径。
SDK stdio / TS / Python有持久化、原生事件和 prompt/query，但当前协议没有 cancel 或 session-close；放弃运行需要关闭整个 runtime。不能满足共享服务下的聊天级停止。换 SDK 语言不能补足协议缺口。
Headless 单次 CLI面向一次性任务，需自行弥合空会话、控制和结构化生命周期差异。不作为 ACP 失败时的降级路径。
桌面/Web 私有接口桌面服务承载用户活动和个人状态；引入端口、鉴权、内部 RPC 与升级耦合。不连接现存服务；模型认证准备可使用独立状态域中的官方 Web UI。

ACP 的恢复调用是 session/resume，不是 session/load；该实现明确不支持 load、历史回放、额外目录、客户端文件系统和终端协议。依据：ACP 契约、SDK 限制。

04 · 架构与进程生命周期

飞书 / Telegram / 本地入口→ChatService FIFO 与槽位→DeepSeekHarnessRunner→ACP Client→独立 dsh + Bridge Policy
  • DeepSeekHarnessRunner 实现 ManagedAgentRunner 和 AgentSessionController。工厂显式分支到该后端，不能落入 app-server 的默认分支。
  • 每个 Bridge 实例持有一个独立 ACP 进程。公共 stdout/stderr 读取器归 Runner 生命周期，单聊天停止不取消公共读取器；RPC 按 id 匹配，update 按 sessionId 路由。
  • NDJSON 双向读写；单个写入队列保证帧不交错。使用结构化协程、Mutex/Channel 与 Dispatchers.IO；不阻塞协程等待 Future，不在调度锁内做外部 I/O。
  • 初始化校验 ACP v1、agent 名称及 list/resume/close 能力；启动时另校验 CLI 发行版本、安装清单及受控 profile。healthy() 用有界的无模型控制请求和进程状态检查，不创建模型轮次。
  • 每个会话最多一个 prompt 在途。全局并发配额仍由 Bridge 管；Harness 既有内部工具并行不等同于新增聊天槽位。

每轮关闭运行作用域，保留持久会话

必须纳入设计：ACP 的 prompt 结束或取消后，晚到子 Agent 消息仍可能触发自主工作。因此不能仅等 prompt 返回就把会话长驻并释放 Bridge 槽位。
  1. 获得 Bridge 槽位后创建或 resume；完成策略约束与绑定落盘后才提交 prompt。
  2. 等待原 prompt 的终态并完成本轮输出归约。
  3. 无论成功、失败或停止，对本轮持有的 session 执行一次 session/close，等待根 Agent、后代、输出链、持久化和作用域清理。
  4. close 确认后才结束 Runner 调用，后续按现有发送/清理流程释放槽位。下一轮恢复同一 ID；close 不删除历史、不清除 Bridge 绑定。

空会话控制命令同样在返回前 close，避免不占模型槽位的控制阶段留下活动 Agent。清理由运行身份绑定，旧轮 finally 不能关闭下一轮的新句柄。V1 受控 profile 禁用自主 goal、job、workflow 入口及其驱动，关闭仍作为后代清理屏障。

BackendId.DEEPSEEK 的配置值固定为 deepseek，展示名 DeepSeek Harness。缺省 backend 的旧配置继续使用 Codex。新增对应内部 RunOptions/解析支持，沿用现有“后端配置决定选型、指定 binary 不切后端”的规则。

  • deepseekProvider/Model 是新会话的初始默认值；恢复会话保留其持久化模型选择。修改默认模型后重启，再 /new 使用新模型。V1 无聊天内模型切换或 Traex 档位策略；缺少精确 route 就明确失败，不静默换模型。
  • 正式环境默认从当前真实 releaseDirectory/libexec/deepseek/ 解析 wrapper、CLI、profile 与策略插件，runtime.json 无需写 binary。wrapper 用绝对 Node 路径启动固定 CLI；向导将解释器路径记为 deepseekNode。deepseekBinary 仅供 DEV/兼容性测试覆盖，必须是与当前 release 一致、带完整性清单的受控 wrapper，普通 CLI 不能绕过策略。禁止守护进程运行 npx 自动下载、引用临时 AppImage 挂载路径、current 链接或可变构建目录。
  • 首次支持版本固定为 0.2.2-rc.1；依赖安装使用锁文件/安装清单。Gradle distribution 明确包含 CLI 及其运行依赖、wrapper、profile 和策略插件，publish manifest 覆盖这些文件。回滚解析目标 release 的完整组合，不能继续引用新版 wrapper。后续版本通过同一协议契约测试后再加入支持范围。
  • deepseekHome 默认本环境 backend/deepseek，设置为子进程 DSH_HOME。会话、凭证、settings、profile、锁及附件与其他环境和桌面 ~/.dsh 隔离；目录重叠检查覆盖真实祖先和符号链接。
  • 进程 cwd 固定为本环境专用 backend/deepseek-launch 目录，不是聊天 cwd，也不是 JVM 隐式 cwd；每次 new/resume 另传聊天绝对 cwd。相对 patch、CLI、状态路径均按明确基准解析，传给子进程前转为绝对路径。
  • 子进程采用业务需要的环境白名单；去除外部 DSH_* 配置、供应商 Key/endpoint 和 Node 注入变量，再显式设置本环境 DSH_HOME、临时目录及 DSH_TELEMETRY_DISABLED=1。固定进程 cwd 避免 Harness 从聊天项目 .env 意外获取认证；专用 launch 目录不能含隐式 .env。

认证与首次向导

bridgectl dev/init 在前台选择 DeepSeek，检测固定 CLI 与 Node，创建独立目录。DeepSeek API Key 使用回环地址上的独立 Harness Web 配置入口；ChatGPT OAuth 通过官方 authorization flow 直接打开浏览器并写入本环境 credential store。向导自动准备路径，用户不需要手写配置或把 Key 贴进飞书。

支持本环境的 DeepSeek API Key，以及 openai-codex 的 ChatGPT OAuth 授权；后者已用 gpt-6.1-sol 完成 ACP 真实调用验证。认证状态通过官方 credential store 的描述接口检查，不读取授权 payload。不得复制桌面或 DEV 的凭证到 PROD；守护重启只检查已有配置，不交互、不覆盖损坏配置。ACP authenticate 成功不等于模型登录成功。

06 · 权限强制是 V1 的实现门槛

Harness base 当前默认 workspace-write + ask。权限会写进 session log，resume 保留旧值；仅配置 DSH_PERMISSION_MODE 或修改默认 patch，无法保证旧 full-access 会话随 Bridge 配置降成只读。ACP 未公开权限设置 RPC。

Bridge 本机配置实际策略审批
read-only（默认）文件写入受限；不能把工具请求拒绝列表当成完整沙箱。never，任何升级请求拒绝。
workspace-write只允许 Harness 沙箱定义的项目写入及平台必要临时区；不自动附加其他目录或共享 Git 根。never，边界外请求拒绝。
danger-full-access显式选择无文件写入限制。never，不出现交互审批。

Bridge 自有策略插件

  • 通过受控 profile/最后一层 patch 加载发布快照内的版本匹配 Cordis 插件，使用公开的 setSandboxMode(session, mode) 与 setApprovalPolicy(session, "never")，不修改上游或增加私有 ACP 方法。
  • 在 fresh/resumed Agent 发布前重申本机权限，覆盖历史 override；在 agent/pre-step 进入前核验并重申，子 Agent 同样受约束。模型任务开始前必须完成策略生效与必要持久化屏障。
  • 将 ACP 服务依赖于策略插件 readiness；插件缺失、加载失败、服务不匹配、无法确认策略时拒绝启动/提交。不能只凭握手成功推断插件已经生效。
  • 由发布快照提供完整受控 profile，校验可加载的 bundle/plugin 清单；禁用模型侧插件管理、配置修改、权限切换、goal/job/workflow 入口及未审计的外部执行插件。保留沙箱化文件/搜索/shell、项目说明、skills、普通子 Agent 与压缩能力；V1 的 mcpServers 固定为空。
  • 权限表和 preset defaults 也固定成本机选择，防止 permission-presets 的新会话初始化覆盖策略；必须验证插件激活、恢复、permission pinning 与 pre-step 的先后顺序。不能通过盲加 prepend 猜测监听器顺序。
  • 收到 session/request_permission 始终拒绝，只返回该请求广告选项中的 reject_once；不构造 allow 结果。原生 ask_user/计划审批不挂交互应答器，返回明确不支持或取消，不模拟用户答案。

Linux/macOS/Windows 的实际沙箱后端、full/partial enforcement 和拒绝行为分别验证。受限模式的 runner 不可用或只能提供未达标的 partial enforcement 时明确失败；V1 不声称限制网络，也不声称能约束任意用户自装插件。策略插件已实现，每次运行时用实际写入探针核实所选沙箱边界；各平台覆盖仍以验证记录为准。策略优先级 · 恢复的权限

07 · 会话、控制命令与提交边界

新会话与持久化顺序

  1. 按现有上下文切换屏障或运行槽位进入；传入规范化绝对 cwd 与 mcpServers:[] 调用 session/new。
  2. 检查 UUID，记录本进程会话句柄和目录；上游 new 在返回前 flush 空会话。普通自动新建：new → onSession 挂起落盘 → onSubmitting → prompt；绑定落盘失败则 close、不提交。
  3. /new：new → close → 返回 descriptor → SessionControlService.activate 原子写入 PENDING → 放行唯一初始化队列 → resume → onSubmitting → prompt。createSession 无 onSession 回调，不得提前修改聊天绑定；close 或绑定落盘失败保留旧绑定。sessionBootstrapExecutesTurn=false。
  4. 新会话初始化沿用 InitialSessionPrompt 和现有 PENDING/SUBMITTING/COMPLETE 记录，不另加一轮测试提示或生成标题请求。

元数据操作超时或被取消后仍由公共 reader 跟踪相关 RPC；若晚到 new 响应产生了空会话，按原 operationId close 它，不提交 prompt、不激活绑定、不重试创建。无法确认创建/清理状态时保留待清理记录，不能将晚到响应交给新操作。

提交是否已发生

ACP prompt 的最终响应是执行完成响应，不提供与 SDK messageId receipt 相同的独立入队确认。不能把“写入 stdin”当成服务端已接受。

  • 发帧前调用 onSubmitting 并持久化 SUBMITTING。明确未写出帧或服务端在 admission 前拒绝时才可调用 onNotSubmitted；一般 RPC 错误不能推断没执行。
  • 当前 session 运行窗口中出现可关联的已提交助手消息/工具事件，或获得可证明已入队执行的正常 prompt 完成结果时，才调用 onSubmitted。thought、usage、配置变化或 cancel 通知不能单独作为依据。
  • 传输中断、进程退出或取消发生在 admission 边界且无法证明是否入队时，保留未知提交状态；不自动重放首轮或普通 prompt。已有 SUBMITTING 的重启保护继续生效。

恢复与目录

SessionKey 继续包含 appId、chatId、topicId、规范化 workspace、runtimeRoot、backendId；当前 SessionStore v5 无需新 schema。UUID 规则通过 validBackendSessionId 统一接入存储、控制服务及新群初始化。

inspectSession(id) 没有 workspace 参数，V1 不新增 registry：在本环境独占状态目录内调用不带 cwd 过滤的 session/list，正确分页，精确匹配 ID，仅返回目标的 id/cwd；不展示其他会话、不读取历史正文。归属仍由 SessionControlService/SessionStore 检查。活动状态来自本 Runner 精确句柄及独占环境锁，不能宣称验证了外部进程；未登记 ID 始终不允许导入。prepareResume 用 session/resume {sessionId,cwd,mcpServers:[]} 让上游核实真实目录和占用。控制阶段完成后 close，正式 prompt 再恢复，若期间状态变化则失败，不自动新建替代。

V1 仅恢复当前隔离域内 Bridge 已登记历史。ACP list 不公开可靠 origin/全机活动证明，因此外部 ID 的 descriptor 保持 externalActivityVerified=false；不得将“同目录”当作私人桌面会话的导入授权。已知缺失、占用、cwd 不符及结果未知均保留旧绑定。

Harness 自身的 inbox 也会持久化。为了保持“Bridge 队列仅在内存、未知提交不自动重放”的契约，策略插件在 agent/created 的 source=resume 屏障清除旧 pending inbox，再重申策略并 flush；不会清除已进入会话历史的消息，也不会清除 fresh 子 Agent 的初始化输入。

/cd 保留忙碌拒绝、目录选择持久化、切回新上下文的规则；/status 显示 DeepSeek、Session ID、当前阶段、队列及停止待确认。未知斜杠命令仍作为用户文本交给模型，不另走 Harness 的命令执行接口。

08 · 正文、进度与结果归约

ACP updateBridge 行为
agent_message_chunk只收当前 session、当前 prompt 窗口；按 messageId 聚合公开文本块，更新预览。每条消息提交后才出现，不能宣传为逐 token 流式。
agent_thought_chunk不进入正文、最终答案或持久化进度文本；不向 IM 转发推理内容。
tool_call / tool_call_update映射为工具开始/完成/失败。允许按现有边界展示名称及有界调用参数；忽略工具返回正文，防止混入答案或日志。
usage_update / config_option_update更新可支持的状态元数据；不视为正文或任务结束。未知可忽略字段保持兼容，破坏路由/终态的变化明确失败。
图片或其他非文本块V1 不拼接 base64；不把二进制写日志。按现有 delivery issue 机制提示未支持内容，只有非文本时不能宣告成功发送了答案。

ACP 不提供 Codex 的 final phase。V1 明确定义：在原 session/prompt 正常返回 end_turn 且本轮 close 成功后，选本轮最后一条有公开文本的已提交助手 message 组作为最终答案；相同 messageId 的多块按序组合，先前消息只作过程。若末尾工具活动后没有新助手正文，不能拿此前工具前正文充当最终结果，返回 EMPTY/EXECUTION。缺失或冲突的 messageId 不猜测消息边界，按协议失败处理。

cancelled → STOPPED；max_tokens 或其他非正常 stopReason → 明确非完整结果，已有正文仅保留为过程；RPC 错误 → 分类失败。迟到更新在 close 期间只排空，不混入已选定结果；close 后旧句柄失效，不能污染下一轮。

通过既有 AgentProgress/AgentRunEvent 和统一文字发送入口输出，复用飞书配置化 CardKit/COT 与 Telegram 现有展示；不加入 Doubao 强制单卡特例。不得把原始 ACP 载荷、推理、工具输出、完整外部错误正文或凭证写入日志。

09 · 停止、故障与整体退出

  1. /stop 仍清理命令接收时已有队列，独立 handle 记录停止意图。prompt 在途时发送 session/cancel {sessionId} 通知；创建/恢复期间先阻止后续 prompt，并关闭本操作持有的 Agent。
  2. cancel 通知没有“停止完成”响应；持续读取原 prompt，等待终态，再 close 本会话。若停止与正常结束竞态，尊重实际终态，不伪造 cancelled；按既有控制语义收束。
  3. 30 秒未完成停止/必要清理时告警并持续占槽。重复 stop 复用同一过程，停止期间新到请求仍等待；不能 kill 共享 ACP 进程或取消公共 reader。
  4. 连接断开但进程仍活着时，所有结果不明运行保留占槽/待确认，不重发、不自动重启后重跑。ACP 没有可承诺的断线重连/快照补齐，展示明确未知状态；由运维重启或整个实例退出解决。
  5. 进程已确认退出时结束相关请求，失败分类保留提交未知；托管进程异常显式接入 FatalErrorHandler/守护恢复，不在不明状态中释放后重跑。建立可恢复外部失败白名单（明确缺失、占用、cwd/参数拒绝、可识别认证/额度/网络失败）；无法分类的故障保留脱敏诊断后调用 FatalErrorHandler.unexpected。不能只抛普通 Exception，现有 ChatTurnExecutor 可能将它转换为 EXECUTION。内部编程异常和 JVM Error 不用宽泛 catch 转成普通业务失败。

Bridge 整体关闭：先停接收与调度，向所有拥有的活动会话请求 cancel/close，关闭 stdin 让 Harness 正常排空退出；整个清理最多等待 5 秒，再终止本实例拥有的 ACP 进程树并等待回收。每项清理以独立 try/finally 保障执行，NonCancellable 只做必要清理，不能继续队列任务。

连接、启动和元数据控制可保留技术超时；prompt 无自动运行/无进展超时。close 超时代表清理结果未知，不能当成功释放槽位。stderr 持续排空但只输出允许的诊断分类、错误码、退出码、运行 ID 及长度统计，不原样转储上游文本；遥测关闭。
