Android 聊天首版

登录后进入会话列表。用户可以接着读桌面会话、创建新会话、在手机上编辑长消息，并在当前会话里看流式回复。首版沿用已部署的 /desktop/* 协议，交付经过签名、R8 和真机验收的 Release APK。

操作流程 接口和状态 流式与弱网 Release 实施与验收

1. 操作流程

会话列表
登录后显示当前服务器的环境、会话标题和运行状态。支持刷新、新建、打开会话。保留查看登录状态和退出的入口。
会话详情
按顺序显示历史提问、答案、可折叠的执行摘要和命令回执。收到流式预览时更新原来的回复卡片。用户在底部时跟随回复，向上翻阅时保留位置，并提供回到底部入口。
长消息编辑
底部多行输入框可展开为全屏编辑器。回车换行，发送用独立按钮。按服务器地址和会话保存草稿，断网、旋转或重新打开 App 后可继续编辑已保存的内容。
首版显示范围
消息采用可选择、可复制的纯文本，保留换行和缩进。原生图片附件用占位显示。Markdown 富渲染、工作区文件和附件下载留给后续版本。斜杠命令继续使用原消息入口，结果显示在命令回执里。

2. 接口和客户端状态

GET /desktop/snapshot
加载或刷新列表。带 conversationId 时返回该会话的完整历史，可用于详情流暂不可用时刷新，以及核对提交是否已受理。
GET /desktop/events
详情前台订阅带 conversationId 的 SSE。首帧加载历史，后续按 requestId 替换预览、状态与最终答案。服务端发送完整的 snapshot，同一段文字只展示一次。
POST /desktop/conversations
发送客户端生成的 UUID id。返回成功或在列表确认该 ID 后打开新会话。
POST /desktop/messages
发送 conversationId、客户端生成的 UUID requestId 和 prompt。响应的 ID 匹配时确认受理，排队、运行和完成以服务器快照为准。

在 Android 模块内增加聊天 API、快照模型、状态管理和页面。复用现有 HTTPS、内存 Bearer、取消请求和一次性 POST 请求体，聊天和认证分别设置超时与响应大小。使用显式 JSON 字段解析为 Kotlin 类型，避免让 UI 直接依赖 JSON，也避免 Release 反射字段重命名问题。

把认证代次、选中会话和请求 ID 用于绑定回调。切会话后的旧事件只会被丢弃。当前登录代次的任一聊天接口返回 401 时取消请求并回到登录页，清掉内存历史，保留当前服务器的本地草稿。服务重启后的任务状态直接显示服务器给出的「未执行」或「结果未知」。

3. 流式回复和弱网

  • 前台单条流。切会话、退后台和退出登录时取消旧连接。回前台后重新订阅。服务端约 30 秒正常结束流，续接时保留历史和滚动位置。异常断线显示重连状态，退避后重试读取。连接持续时间与模型运行时间独立。
  • 完整快照。按 UTF-8 的 SSE 事件边界解码，完整解析后再更新界面。相同 revision 仍可能携带不同执行状态。使用按请求 ID 键控的懒列表，解析移出主线程。初定快照和单帧 SSE 数据上限 8 MiB，验收时用长历史校验内存和流量。超限时保留最近一次成功内容，提示使用桌面端查看该会话，并停止对超大帧自动重试。现有接口一次返回全部历史。
  • 提交前留存。先把生成的 ID 和原请求体保存到应用私有存储，再发请求。文本校验遵守服务端的 32,000 UTF-16 代码单元和序列化后 128 KiB 两层限制。每个会话同一时间只处理一个未确认提交，服务端一旦确认受理，用户就可以继续发下一条。
  • 提交结果未知。响应丢失、断网或代理返回 5xx 时保留草稿及待确认记录。重连后按 ID 查列表或历史。找到即确认，查不到时可手动用同一 ID 和原内容重试。明确的 400 显示拒绝并保留文本。退出或重新登录都不会触发重发。清理已确认的草稿时保留用户后来输入的新内容。

4. Release 打包与签名

  1. 先跑 Release 基线。沿用当前 Gradle 9.5.0、AGP 9.3.0、JDK 21 和 minSdk 24。用 AGP 的 release { optimization { enable = true } } 开启 R8 与资源优化，先验收现有登录退出，再加入聊天。沿用依赖的 consumer rules。只为可复现的缺失入口补精确 keep 规则。用 Release lint 检查新增 Android API 的最低版本兼容性。
  2. 固定应用签名。保留包名 top.ntutn.agent.bridge.android。首版聊天拟用 versionCode 2、versionName 1.1.0。使用本项目长期发布密钥，私钥和密码存放在仓库外。构建后先校验对齐，再用 Android SDK 的 apksigner 签名并校验签名指纹、包名、版本和 APK SHA-256。按构建保留 R8 mapping.txt，用于还原崩溃栈。
  3. 验证实际交付 APK。安装签名后的同一份 APK 做冷启动、登录和聊天验收。当前 NX888J 上是 Debug 签名的同包名客户端，首次 Release 需要独立设备或模拟器，或经确认后在真机卸载 Debug 再安装。后续用同一发布密钥和递增版本号覆盖升级。

5. 实施顺序与验收

  1. 确认 Release 基线和签名流程，再完成只读列表、历史和 SSE。
  2. 实现创建会话、发送、全屏输入和本地草稿，接上幂等重试与会话失效处理。
  3. 先用模拟后端复现超时和乱序，再安装签名后的 Release APK 连接 dev 验收。采用真机或模拟器覆盖最低支持版本的冷启动和登录。
聊天通路
读取桌面会话和完整历史，新建会话，发送中文多行文本和第二条排队请求。看见流式预览和完整终态。滚动查看历史时新事件不抢滚动。
断网与重连
覆盖离线写草稿、发送后丢响应、快速切会话、旋转、切后台和杀进程重开。验证同一请求只执行一次、约 30 秒的正常续接和过期重新登录。
异常输入与大历史
覆盖超长输入、JSON 转义后超限、非预期 JSON、SSE 分片、同 revision 不同状态及超大历史。异常能显示明确错误并返回可操作状态。
发包门槛
签名和 R8 产物校验通过，安装后在上述路径没有崩溃或 ANR。记录 APK 校验值、设备和系统版本、实际覆盖用例及结果。
