AGENT / BRIDGE · DESKTOP V1

本地 Agent 的中文桌面工作台

原生 Compose 窗口连接常驻 Bridge。复用现有后端、队列和停止语义，窗口与模型进程生命周期独立。

这一版能做什么

会话与历史创建会话、保存输入与完整最终答案、重新打开查看历史；断线重连不会重新提交任务。
执行与停止实时答案预览、可展开的执行摘要、同会话 FIFO 排队、等待后端确认的停止。
目录与环境空闲时选择工作目录；显示实际访问模式；显式切换 dev / prod 与自定义状态根目录。

首版采用附着现有服务的模式，需要已初始化的飞书或 Telegram Bridge。每个服务实例仍使用一个配置好的后端（Codex、Traex 或 OpenCode）。桌面新建自己的会话，不向 IM 发送回复，也不导入旧 IM 聊天。桌面和 IM 共用同一调度器与并发上限。

审批按钮、每会话选择后端、Git diff、worktree、终端与完整工具事件时间线不在本版范围。执行摘要和实时答案沿用当前后端的有界预览，最终答案不按预览上限截断。权限来自本机配置，重启服务生效，GUI 不修改权限。

构建与运行

在仓库目录执行；核心及桌面统一使用 JDK 21，原生打包使用 JDK 21 的 jpackage。本次开发在 macOS 上验证，Linux 打包需要在 Linux 构建并验收。

./gradlew test installDist :desktop-app:createDistributable

# 运行桌面开发版本，连接 dev
./gradlew :desktop-app:run --args="--env dev"

# 指定自定义状态根目录
./gradlew :desktop-app:run --args="--root /absolute/bridge-root --env dev"

# 在 macOS 生成 DMG（可选）
./gradlew :desktop-app:packageDmg

# 验证经过 ProGuard 处理的 Release DMG
./gradlew :desktop-app:packageReleaseDmg

Release 使用 Compose 默认的 ProGuard 7.7，项目字节码和打包运行时固定为 JDK 21。createDistributable 不执行 Release 的 ProGuard 步骤，不能替代 packageReleaseDmg 验证。Release DMG 位于 desktop-app/build/compose/binaries/main-release/dmg/。desktop-app/proguard-rules.pro 忽略 OkHttp 可选的 Android 与第三方 TLS 提供者缺失警告；同时保留 Okio 裁剪，但禁止其字节码优化，规避 ProGuard 7.7 对 buffer(Source) 返回类型特化导致的 VerifyError。桌面使用随应用打包的 JDK TLS 实现。Release 验收必须确认服务连接和会话加载，仅确认窗口启动不足以覆盖网络字节码路径。

macOS 可直接双击 desktop-app/build/compose/binaries/main/app/Agent Bridge.app，应用自带 JVM。也可通过 open "desktop-app/build/compose/binaries/main/app/Agent Bridge.app" 启动。默认状态根目录为 ~/.agent-im-bridge-kt，默认环境为 dev；连接 prod 需在设置中明确选择或使用 --env prod。

只有包含本次 API 的 Bridge 版本才能连接桌面。生成桌面包或运行 Gradle 不会升级现有 dev/prod 服务，也不会触发模型登录。

让现有服务支持桌面

保留不可变发布和守护部署流程。先构建，再发布快照并选择需要升级的环境；部署会排空已有任务。

./gradlew test installDist
./bridgectl publish
# 使用 publish 输出的实际版本号
./bridgectl deploy --env dev --release r-实际版本号
./bridgectl deploy-status 部署编号
./bridgectl status --env dev

首次使用、尚未绑定机器人时，在本机前台终端运行 ./bridgectl dev 完成向导。正式环境升级沿用同样流程并明确指定 --env prod。不从 build/install 直接运行 Bridge JVM，不修改 releases 内的已有文件。

Markdown 消息

用户输入和 Agent 回答支持 Markdown、代码高亮与复制、可横向滚动的宽表格，以及工作目录内图片和 HTTPS 图片。原文持久化不变。详细行为、JDK 21 迁移和验收步骤见 Markdown 接入说明。

日常使用

  1. 看到左下角已连接的环境和后端后，点击“新建会话”。
  2. 按需“选择目录”。忙碌时禁用目录切换；切到其他目录会清除该目标目录旧绑定，返回该目录也会开启新上下文。
  3. 输入内容，点击“发送”或按 ⌘ / Ctrl + Enter。同一会话运行中可继续加入队列。
  4. 点击“停止当前会话”后等待后端终态；旧任务的停止按钮不会影响新一轮。停止后新入队的消息等待清理结束再运行。
  5. 关闭窗口仅断开客户端。再次连接可查看历史；网络错误不会自动重新发送 prompt。提交结果未确认时，使用“重试”复用原请求 ID。

保留 /status、/pwd、/help、/stop、/cd 控制命令，未知斜杠命令交给 Agent。服务重启后，原本排队但尚未启动的请求标记未执行，已启动但没有终态的请求标记结果未知；都不会自动重跑。

本地接口与数据

桌面只读取当前环境的 control/endpoint.json 来发现服务，实际历史和操作通过 loopback HTTP/SSE 完成。Bearer 令牌不写入界面或日志；不开放 CORS，也不监听外部网卡。

接口用途
GET /desktop/snapshot?conversationId=UUID会话列表、选中会话的历史、工作目录、调度状态和实例元数据。
GET /desktop/events?conversationId=UUIDSSE snapshot 事件，携带完整当前视图。连接按技术时限续接，客户端重新发现实例并验证 bootId；不靠事件重放触发模型。
POST /desktop/conversationsJSON：id（客户端 UUID）。重复创建相同 ID 返回已有会话。
POST /desktop/messagesJSON：conversationId、requestId、prompt；停止可附 targetRunId。重复请求只查询/确认原提交，内容冲突返回 400。

请求与最终回复存于环境目录的 desktop/<namespace>/history.json，与诊断日志分开，使用私有文件权限和原子替换。namespace 按应用、后端与模型状态根目录隔离；原生会话绑定仍由 SessionStore 唯一管理。流式预览只保留在内存中，最终答案和收束摘要持久化。第一版为每个命名空间最多 500 个会话，每会话 2000 个请求，每条输入 32000 字符，达到上限会明确拒绝而非删除旧历史。

隔离验证

# 全部离线回归与部署测试
./gradlew test installDist

# 可选：启动模拟服务，不连接机器人、不调用真实模型
./gradlew desktopSmokeServer
# 把输出的 DESKTOP_SMOKE_ROOT 作为桌面的 --root 参数
./gradlew :desktop-app:run --args="--root /输出的临时目录 --env dev"

模拟服务只存在于测试源码，数据在独立临时目录；结束该前台 Gradle 进程会清理模拟服务。验证可覆盖创建会话、实时预览、停止、目录选择、窗口重开与断线提示。真实 Codex 测试保持显式 opt-in，不属于默认测试。

新增回归覆盖本地鉴权、持久化前置、幂等提交、完整长答案、IM/桌面回复隔离、共享并发上限、FIFO、失败后出队、原生停止确认、旧停止目标、SSE 断开、目录切换、重启未知状态及退出清理；既有后端与 IM 测试继续保留。
